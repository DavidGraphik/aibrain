# Security

Do not put credentials, employee/customer data, protected installation configuration, backups or access links in issues, pull requests or commits. Use your organization's established private security channel for sensitive reports; do not publish exploit details or personal data in a public issue.

Provider authorization, installation/user isolation, scoped file roots, signed identities, replay protection and native sandbox boundaries remain required. Example configuration is not production configuration. Changes to these boundaries need focused negative tests and native acceptance before deployment.
